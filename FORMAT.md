# Diff Format

This document specifies the marshalled diff format used by `jsondiffr`. The same format is consumed by `patch(a, d)` and produced by `diff(a, b)`. The format is designed to be small (it omits unchanged data) and to round-trip back to the modified structure when applied to its source.

The format specification aims to be stable. In case changes are needed, backwards-compatibility is prioritized, such that a diff generated by an older compliant implementation can be correctly applied using a more recent compliant patch() implementation.

The specification is language agnostic but uses Python syntax and examples. For historical reasons, syntax for supporting Python sets is described, but **sets are not supported**.

## 1. Marshalled format

### Example

Given a source

```json
{"name": "Alice", "skills": ["Python", "Django"], "obsolete": true}
```

and a target

```json
{"name": "Alice", "skills": ["Python", "Django", "Flask"]}
```

the marshalled diff, written to a JSON file, looks like:

```json
{
  "skills": {
    "$insert": [[2, "Flask"]]
  },
  "$delete": ["obsolete"]
}
```

`$insert` and `$delete` are **sentinels** — special keys that signal structural operations rather than ordinary data. The rest of this section defines them precisely and explains the in-memory ↔ marshalled translation.

### Structure

A diff value `d` is a JSON-like structure: a `dict`, `list`, `set`, scalar, or `None`. Structural operations are signalled by five **sentinels**. In the marshalled (string-encoded) form each appears as `$<label>`. The escape prefix is always the literal `$`.

| Marshalled  | Used in           | Meaning                                |
| ----------- | ----------------- | -------------------------------------- |
| `$replace`  | any container     | Wholesale replacement of the value     |
| `$delete`   | dict / list       | Remove keys (dict) or positions (list) |
| `$insert`   | list              | Insert `(position, value)` pairs       |
| `$add`      | set (unsupported) | Add elements                           |
| `$discard`  | set (unsupported) | Remove elements                        |

### The empty diff

An empty dict `{}` at any level means **no change**.

### Marshaling and unmarshaling

Structurally, a sentinels appears like any other key in the JSON sring representation of the diff, so escaping is needed to prevent certain data strings being confused with sentinels.
The escaping is called marshalling, and consist of adding a `$` character in front of *any* `$`-prefixed string appearing as a key *or* a value in the marshalled JSON string representation:

| Input                                     | Marshalled output |
| ----------------------------------------- | ----------------- |
| A sentinel (e.g. `replace`)               | `"$replace"`      |
| A string `"$x"` already starting with `$` | `"$$x"`           |
| Any other string                          | unchanged         |
| `dict`, `list`                            | recursed into     |

Unmarshalling is the inverse: `"$foo"` decodes back to a sentinel if `foo` is a known label, otherwise it strips a single leading `$`. Marshalling and unmarshalling are inverses on any diff.

## 2. patch() behavior

`patch(a, d)` produces a value `b` from a source `a` and a diff `d`. The result is fully determined by the structure of `d` and the type of `a`. Sub-patches are applied recursively.

### Dispatch rules

1. If `d` is **not a dict**, return `d` (replacement: `d` is the new value).
2. If `d` is the **empty dict** `{}`, return `a` unchanged.
3. If `d` is a dict and contains the `replace` sentinel, return `d[replace]`.
4. Otherwise the action depends on `type(a)`:

#### When `a` is a `dict`

Copy `a`. For each `(k, v)` in `d`:
- if `k` is `delete`: for each key in `v`, remove it from `a`;
- else if `k` is **absent** from `a`: set `a[k] = v` verbatim (insertion);
- else: recurse — `a[k] = patch(a[k], v)`.

#### When `a` is a `list`

Copy `a` into a list, then:
- if `delete` in `d`: pop each position in `d[delete]` from the list in the order given. Positions refer to indices in the **source list** and are expected to be in **descending order**, so sequential `pop()` does not shift later targets.
- if `insert` in `d`: for each `(pos, value)` in `d[insert]`, insert `value` at `pos`. Positions refer to the list at the moment of insertion.
- for every other key in `d` (which must be an integer): treat the key as a position in the **final list** (after deletes and inserts) and recursively patch — `a[int(k)] = patch(a[int(k)], v)`.

#### When `a` is a `set` (unsupported)

Copy `a`. Then:
- if `discard` in `d`: remove every element in `d[discard]` from the set;
- if `add` in `d`: add every element in `d[add]` to the set.

#### When `a` is a scalar

If none of the above branches match, return `d` if `d` is also a scalar (the diff is the new value). If `d` is not a scalar (but `a` is), returning an error is recommended but a mere warning is also allowed.

### Empty diffs and replacement

The empty dict `{}` always means **no change**, regardless of `a`'s type. A non-dict `d` is always treated as a wholesale replacement: `patch(a, [1, 2, 3]) == [1, 2, 3]`.

### No reverse operation

The format only supports forward application. There is no `unpatch(b, d) → a`; the diff retains only the information needed to go forward.

## 3. diff() behavior

`diff(a, b)` produces a diff `d` that `patch()` can apply to `a` to obtain `b`. The shape of `d` is determined by the types of `a` and `b`.

### Top-level dispatch

| Case                                            | Result                                                       |
| ----------------------------------------------- | ------------------------------------------------------------ |
| `a is b` (identity) or `a == b` (equal scalars) | `{}`                                                         |
| Type mismatch (e.g., `dict` vs `list`)          | `b` directly if `b` is not a dict; `{replace: b}` if it is   |
| Scalar inequality (same scalar type, unequal)   | `b` directly                                                 |
| Both `dict`                                     | See *Dict diff*                                              |
| Both `list`                                     | See *List diff*                                              |
| Both `set`                                      | See *Set diff*                                               |

### Dict diff

The differ partitions `b`'s keys into **added** (not in `a`), **changed** (in both, with recursive sub-diff and a similarity score), and **removed** (in `a`, not in `b`). A similarity score `s ∈ [0, 1]` aggregates per-key similarities. Then:

- if `s == 0` (nothing in common), emit `{replace: b}`;
- if `s == 1` and nothing was added, changed, or removed, emit `{}`;
- otherwise, either (a) emit `{replace: b}` or (b) emit a dict containing the changed-or-added keys mapped to their sub-diffs (for changed) or new values (for added), plus `delete: [<removed-key>, ...]` if anything was removed.

For the last case (`0 < s < 1`), the differ may choose the best option based on `s`, another heuristic such as size of the diff, speed of generating the diff, or user preference.

Sub-diffs that resolve to `{}` (unchanged) are omitted entirely.

### List diff

The differ runs an LCS-based comparison between source and target. Each step is classified as `inserted`, `deleted`, or `changed` (matched but not identical). A similarity score `s ∈ [0, 1]` aggregates per-element similarities. Then:

- if `s == 0`, emit `b` directly (the full target list);
- if `s == 1` and nothing was inserted, changed, or deleted, emit `{}`;
- otherwise, either (a) emit `b` directly or (b) emit a dict:
  - integer keys for each changed element, mapping the **target position** to a recursive sub-diff;
  - `insert: [(target-position, value), ...]` for each inserted element, in trace order;
  - `delete: [<source-position>, ...]` for each deleted element, in **descending order** so the patcher's sequential `pop()` does not shift later targets.

For the last case (`0 < s < 1`), the differ may choose the best option based on `s`, another heuristic such as size of the diff, speed of generating the diff, or user preference.

### Set diff (unsupported)

The differ computes **added** = `b - a` and **removed** = `a - b`, plus a similarity score from the best pairwise matching between them. Then:

- if `s == 0` or every element of `a` was removed, emit `b` directly;
- otherwise (a) emit `b` directly or (b) emit a dict with optional `add: <added-set>` and `discard: <removed-set>`.

### Special cases

- `diff([], <non-empty list>) → <non-empty list>` (the target list itself).
- `diff(<non-empty list>, []) → []`.
- `diff({a: 1}, {b: 2}) → {replace: {b: 2}}` — wrapped because the target is a dict and an unwrapped `{b: 2}` would be ambiguous with a dict-patch.

## 4. Invariants

- `patch(a, diff(a, b)) == b` for all JSON-compatible `a`, `b`.
- `diff(a, a) == {}`.
- Marshalling and unmarshalling are inverses on any diff.
- The format does **not** support reversal: there is no `unpatch(b, d) → a` operation.

## 5. Worked examples

### 5.1 Dict edits

```python
>>> diff({'a': 1, 'b': 2}, {'b': 3, 'c': 4})
{'b': 3, 'c': 4, delete: ['a']}
```

- `'a'` removed → listed under `delete`.
- `'b'` changed: scalar inequality → diff value is the new scalar `3`.
- `'c'` added → maps directly to its new value `4`.

### 5.2 Nested edits with similarity

```python
>>> diff({'a': [0, {'b': 4}, 1]}, {'a': [0, {'b': 5}, 1]})
{'a': {1: {'b': 5}}}
```

- The list at `'a'` is mostly the same; only the element at target position 1 changed.
- That element is a dict whose only edit is `'b': 4 → 5`, encoded as `{'b': 5}`.

### 5.3 List with insertion, deletion, and change

```python
>>> diff(['x', 'a', {'v': 11}, 'c', 'x'], ['a', {'v': 20}, 'b', 'c'])
{insert: [(2, 'b')], delete: [4, 0], 1: {'v': 20}}
```

Applied to source `['x', 'a', {'v': 11}, 'c', 'x']`:

1. `delete: [4, 0]` → pop position 4 (`'x'`), then position 0 (`'x'`): `['a', {'v': 11}, 'c']`.
2. `insert: [(2, 'b')]` → insert `'b'` at position 2: `['a', {'v': 11}, 'b', 'c']`.
3. Key `1`: patch element at position 1 with `{'v': 20}`, recursing into the dict: `['a', {'v': 20}, 'b', 'c']`.

### 5.4 Sets (unsupported)

```python
>>> diff({1, 2, 4}, {1, 2, 3})
{add: {3}, discard: {4}}
```

### 5.5 Whole-value replacement (mixed types)

```python
>>> diff({'a': 1, 'b': 2}, 123)
123
>>> diff([1, 2], {'c': 3, 'd': 4})
{replace: {'c': 3, 'd': 4}}
```

The second is wrapped in `replace` because the target is a dict and would otherwise be indistinguishable from a dict-patch on the source.

### 5.6 Equal inputs

```python
>>> diff({'a': 1}, {'a': 1})
{}
```

The empty dict means "no change". `patch(a, {}) == a`.

# Version history

Current release of the specification: `v3.0.0`

Versioning is similar to Semantic versioning:
- a patch release corresponds to a clarification without changes to substance
- a minor release adds features in a backwards-compatible manner
- a major release introduces breaking changes

`v3.0.0` is the first formal release. It matches the "compact" format generated by [jsondiff.diff(source, target)](https://github.com/xlwings/jsondiff) (v2.2.1), except that:
- Python sets are not supported.
- The escape character for sentinels is hardcoded as `$`.
